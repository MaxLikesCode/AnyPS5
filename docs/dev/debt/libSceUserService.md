# libSceUserService technical debt

### Unknown function info

- [sceUserServiceGetNpAccountId](../../../core/libs/prx/libSceUserService/Export.cpp) (libSceUserService) - the account id for a user with no linked PSN account is assumed to be 0 with success; libSceNpManager's `sceNpGetAccountIdA` answers the same question with `SCE_NP_ERROR_SIGNED_OUT`
- [sceUserServiceInitialize, sceUserServiceTerminate](../../../core/libs/prx/libSceUserService/Export.cpp) (libSceUserService) - measured on a PS5 (firmware 13.60): before `sceUserServiceInitialize`, and again after `sceUserServiceTerminate`, `sceUserServiceGetLoginUserIdList`, `sceUserServiceGetEvent` and `sceUserServiceTerminate` return `0x80960002`; a second initialization returns `0x80960003`, and a new initialization reports the login of the initial user again. The other calls were not measured before initialization and do not check it. The prosper console oracle measured the thread priority check of both initializations ([measured](https://github.com/mattias800/prosper/blob/3ea5cb9a846b6dcd00f5073360462bbda4f72288/prosper/tests/data/console_oracle/userservice.golden.tsv#L18-L30)): `sceUserServiceInitialize` reads the priority from the first `int32_t` of its parameters and `sceUserServiceInitialize2` takes it as its first argument, as prosper also reads from the library's code ([read](https://github.com/mattias800/prosper/blob/3ea5cb9a846b6dcd00f5073360462bbda4f72288/prosper/src/hle/service/hle_service.cpp#L128-L146)). A priority outside 256 to 767, negative ones included, returns `0x80960005` whether or not the service is initialized, and a valid one returns `0x80960003` when it is. Null parameters are accepted; prosper reads a default priority of 700 for them, which is not needed here because no service thread exists. [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/UserService/UserService.cs#L94) declares a second `cpuAffinityMask` argument for `sceUserServiceInitialize2`; it is not read, for the same reason, and the console's check of it is unknown. A first `sceUserServiceInitialize2` with a valid priority was not measured: it initializes like `sceUserServiceInitialize`
- [sceUserServiceGetUserColor](../../../core/libs/prx/libSceUserService/Export.cpp) (libSceUserService) - the default profile colour is assumed to be blue (0)
- [sceUserServiceGetUserName](../../../core/libs/prx/libSceUserService/Export.cpp) (libSceUserService) - `0x80960105`, which a PS5 (firmware 13.60) returns for a user id it does not know, has no known name; it is `USER_SERVICE_ERROR_UNKNOWN_USER` here. On the console a registered user who is not logged in still gets their name; here only the initial user exists
- [sceUserServiceGetAgeLevel](../../../core/libs/prx/libSceUserService/Export.cpp) (libSceUserService) - on a PS5 (firmware 13.60) the value is the age set in the user's parental restriction (0, 7, 12 and 15 were measured) and `0xFFFFFFFF` without one; a user who is not logged in returns `0x80960009` with or without an output. Parental restrictions are not modelled, so the initial user is always reported as unrestricted. PPSA12544 (Unity) only stores the value for its user profile
- [sceUserServiceGetAccessibilityChatTranscription, PressAndHoldDelay, TriggerEffect, Vibration, ZoomEnabled, ZoomFollowFocus](../../../core/libs/prx/libSceUserService/Export.cpp) (libSceUserService) - report 0, 0, 1, 1, 0 and 1, what a PS5 (firmware 13.60) reports for a user whose accessibility settings are all at their defaults; the console reports the user's own settings (a changed vibration intensity read 3), which are not modelled. What each number means is unknown. A user who is not logged in returns `0x80960009` with or without an output
- [sceUserServiceGetAccessibilityKeyremapEnable, sceUserServiceGetAccessibilityZoom](../../../core/libs/prx/libSceUserService/Export.cpp) (libSceUserService) - declared without parameters as throwing stubs calling `NotImplemented_nid_no_patch`. Their signatures and values remain unverified on hardware
